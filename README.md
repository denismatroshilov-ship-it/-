# tiktok-tg-studio

Нарезки сильных моментов из существующих фильмов под TikTok + воронка в
Telegram-канал: превью с аппрувом в канал → автопубликация в TikTok по
расписанию.

Видео здесь не генерируется нейросетями и не должно: источник — только кадры
самих фильмов. Higgsfield в проекте выступает исключительно транспортом
публикации (заливка готового mp4 и постинг в TikTok).

Правила формата (что делает ролик залетающим) не в голове и не в README, а в
`app/playbook.py` — генератор сценариев и валидатор дёргают одни и те же
цифры. Откуда цифры — `docs/trends.md`.

## Как это работает

```
/hooks <сцена>  →  5 вариантов сценария: хук, раскадровка, подпись

/clip <файл> <12:30-12:58> <хук>
        ↓ ffmpeg: обрезка, 9:16, хук вжигается в первые 2 с, loudnorm
        ↓ превью в TG-канал (кнопки ✅/🗑) + предупреждения валидатора
        ↓ approved
   cron-слоты  →  TikTok publish
```

Состояния ролика в очереди: `new → cutting → awaiting_approval → approved →
publishing → published`; при ошибке — `failed`, при отказе — `rejected`.
Публикация в TikTok при сбое возвращает ролик в `approved`, так что следующий
тик расписания попробует снова.

## Запуск

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env    # заполнить токены
python -m app.main
```

Бот должен быть админом канала `TG_CHANNEL_ID` (право постить и редактировать
свои сообщения). Канал задаётся числовым id или `@username`. Кнопки аппрува
слушаются только от `TG_ADMIN_IDS`.

На старте выполняется preflight: проверяются токен, доступность канала и то,
что бот в нём админ. Если что-то не так, сервис падает сразу с внятной
ошибкой, а не через полчаса на первой публикации.

## Команды бота

| Команда | Что делает |
| --- | --- |
| `/hooks <сцена>` | 5 сценариев под сцену — по одному на каждый архетип хука |
| `/clip <файл> <тайминг> <хук>` | режет момент из фильма в `SOURCES_DIR` |
| `/caption <id> <текст>` | меняет подпись перед публикацией |
| `/queue` | сводка по статусам |
| `/publish` | публикует ближайшую партию, не дожидаясь слота |
| `/accounts` | список подключённых TikTok-аккаунтов |

## Нарезка

Исходники кладутся в `SOURCES_DIR` (по умолчанию `./sources`), в репозиторий
не коммитятся. Тайминг — `12:30-12:58` или `12:30-+25` (длительность в
секундах), для длинных фильмов `01:12:30-01:12:58`.

```
/clip gladiator.mp4 12:30-+24 Один дубль. Камера не выключалась
```

Что делает ffmpeg: режет отрезок, кладёт кадр по центру на размытый фон
1080×1920 (кроп резал бы лица и субтитры), вжигает хук белым с обводкой на
первые 2 секунды с переносом по словам, нормализует громкость до −14 LUFS,
чтобы TikTok не пережал звук по-своему.

Перед отправкой на аппрув ролик проходит `playbook.validate`: длина вне
12–34 с и слишком длинный или пустой хук приезжают предупреждением прямо в
подпись превью. Это предупреждение, а не запрет — публиковать можно.

Требуется `ffmpeg` и `ffprobe` в PATH плюс шрифт DejaVu
(`apt install ffmpeg fonts-dejavu`).

## Про копирайт

Формат построен на чужих фильмах, и главный риск — не суд, а платформа:
Content ID снимает ролик, повторные страйки снимают аккаунт, монетизация на
таком контенте не включается. Отсюда и вся конструкция: короткие отрывки,
свой слой поверх (хук, разбор, подпись) и Telegram как актив, который не
отберут вместе с TikTok-аккаунтом. Подробнее — в `docs/trends.md`.

## Настройки

Все — через `.env`, см. `.env.example`. Ключевое:

- `PUBLISH_CRON` — слоты публикации, **в UTC** (по умолчанию 09:00/15:00/20:00).
- `PUBLISH_BATCH` — сколько роликов выпускать за тик.
- `AUTO_APPROVE=true` — публиковать без ручного аппрува (превью в канал всё
  равно уходит, но уже без кнопок).
- `TIKTOK_ACCOUNT_ID` — взять из `/accounts`. Пока не задан, одобренные ролики
  копятся в очереди, а в канал падает предупреждение.

## Подключение TikTok-аккаунта

OAuth-привязка делается на стороне Higgsfield (`tiktok_connect`), после чего
аккаунт виден в `/accounts`. Токен живёт ограниченно — если публикация начнёт
отдавать ошибку авторизации, аккаунт надо переподключить.

## Про эндпойнты Higgsfield

REST-пути собраны константами в начале `app/providers/higgsfield.py`
(`EP_MEDIA_UPLOAD`, `EP_TIKTOK_PUBLISH` и т.д.), а разбор ответа устойчив к
нескольким вариантам формы (`video_url` / `url` / `results[]`). Если в аккаунте
включена другая версия API, правится одним местом. Перед первым боевым запуском
стоит прогнать `/accounts` — это самый дешёвый способ проверить, что ключ и
базовый URL верные.
